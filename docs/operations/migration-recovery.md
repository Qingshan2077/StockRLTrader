# 存储维护、历史导入与恢复

本文件是后续操作说明，不表示本次已运行维护命令或修改用户数据。应用不会读取或迁移根目录旧 `experiments.db`。

## 显式维护

```powershell
python -m stockrl_app.maintenance init
python -m stockrl_app.maintenance check
python -m stockrl_app.maintenance backup outputs/backups/state-before-change.sqlite3
python -m stockrl_app.maintenance import-legacy
```

`init` 仅创建新应用 schema 或接受已知当前 schema；未知版本拒绝写入。`backup` 使用 SQLite 一致性备份接口包含已提交 WAL 内容，目标文件必须不存在。升级入口是 `migrate <新备份路径>`，目前只接受已有当前版本，没有实现任意版本降级或虚构迁移。

完整备份还需保留 `outputs/app/` 中的快照、配置和 `outputs/experiments/` 产物。停止 worker 并确认计算子进程结束后，再复制目录及生成数据库备份，使文件与索引处于稳定状态。不要直接复制一个正在写入的 SQLite 主文件并丢弃 WAL。

`import-legacy` 扫描配置输出根目录下的原始 RL 目录和一层旧 replay 目录，只创建索引，不修改源文件；按相对目录与摘要指纹去重。带 manifest 的新应用目录不冒充 legacy-v0，需恢复其原应用数据库。没有任务记录的历史产物显示“历史产物”，不伪造成功任务。

旧实验的算法、交易参数和切分按只读配置展示，无法确认的字段保持未知。报表结构完整但模型来源丢失时仍可浏览，不能重放；模型只在重放计算子进程内加载。未知协议、损坏文件与来源缺失分别处理。移动旧 replay 后其原始来源可能无法重新定位，此时禁用重放，不按摘要任意绝对路径访问其他目录。

## 任务恢复

API 重启不影响独立 worker。关闭浏览器不取消任务。通过启动器退出时先请求停止领取和取消正在执行的任务，等待退出确认。

worker 使用协调实例锁与独立计算锁。重启发现旧计算仍占锁时进入恢复等待，不领取下一任务，不凭一个过期 PID 杀进程。控制通道丢失后，旧计算在下一个安全检查点退出；若底层调用阻塞，需确认并停止实际旧实例，不能删除锁文件来冒充任务已退出。

正常取消先显示“取消中”，15 秒未退出则终止其自有子进程，并等待 5 秒确认。未确认退出不能显示“已取消”。单任务总时限为 12 小时，超限经过同样的受控停止过程后标记失败。失败、取消和中断不自动重试，不支持断点续训。

完成文件先写入 `.staging/<job_id>/`。发布先登记意图，再进行最终移动与数据库成功事务。若在两者之间崩溃，重启后核对 owner、revision、manifest 指纹及取消状态，有可信凭据才补记成功；其余保持隔离诊断文件。不得手工把任务改成 succeeded，也不要覆盖已有完成目录。

## 常见状态

| 状态 | 处理方式 |
|---|---|
| worker 离线 | 可以浏览和排队；检查 worker 本地日志与启动状态 |
| 恢复等待 | 确认旧计算是否仍占锁，停止实际旧实例后重启协调器 |
| schema 不兼容 | 停止写操作，恢复对应代码/依赖或使用明确支持的维护迁移 |
| 文件指纹改变 | 检查数据是否移动、编辑或损坏；从完整备份恢复，不跳过指纹校验 |
| 前端未准备 | 在获得后续执行授权后构建前端；启动器不会代为构建 |
| 请求连接中断 | 不假定提交失败；保留相同幂等标识重试，或按已有任务 ID 查询 |

## 回退

回退应用代码或使用旧 CLI 不删除数据，也不自动降级新 SQLite。先保存配置、一致性数据库备份和产物目录，再切换代码与匹配依赖。旧 CLI 忽略新应用数据库，并继续读取核心布局的模型与报表。此次没有切换 main、推送远端或演练恢复，所有恢复保证仍须后续故障注入验证。
