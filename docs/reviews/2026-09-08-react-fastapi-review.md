## 1. 总体判断

现有项目适合继续作为单资产 RL 研究引擎。下一步采用 React + FastAPI 的合理目标，是把实验配置、任务运行、结果浏览与 Python 研究计算分开，让实验不依赖某个浏览器会话，并建立前后端可独立协作的接口。

“整体重构”应覆盖应用的全部工作流和运行方式，但没有理由重新实现已经独立的账户、特征和训练算法。默认采用同一仓库中的分层应用，保留 `stockrl/` 的计算语义，新增应用服务和独立任务进程，最后替换 Streamlit 默认入口。项目复杂度会增加，收益需要通过任务可靠性、接口清晰度和完整功能迁移体现。

框架迁移不会证明 RL 有额外投资价值。研究目标、信息来源、风险匹配比较和跨时期检验仍然需要单独论证；本次不把它们包装成已经解决的问题。

## 2. 现有架构与证据

| 现有职责 | 本地证据 | 迁移含义 |
|---|---|---|
| Streamlit 页面直接加载数据、调用实验并读结果 | `frontend/app.py` 的 `_init_state`、`_saved_summaries`、`_load_saved_summary` 和运行实验按钮 | 浏览器状态、应用编排与文件访问需要分开 |
| 同步实验函数顺序执行多个 seed | `stockrl/experiments.py::run_experiment` | 可作为 worker 的计算入口，不应直接放入长时间 HTTP 请求 |
| 验证检查点与有限进度回调 | `stockrl/training.py::ValidationCheckpoint` | 已有进度接口可扩展；没有持久任务、取消或恢复协议 |
| 最后写 summary，保存模型、归一化和逐日记录 | `stockrl/experiments.py` | 有可复用产物，尚无完整任务状态和原子发布协议 |
| 单个目录原样重放 | `stockrl/experiments.py::evaluate_saved_run` | 应保留 CLI 和重放语义，不能把重放当作新的独立样本 |
| 单一环境负责训练、评估和基准记账 | `stockrl/env.py`、`stockrl/evaluation.py` | 作为迁移保护线，不能让前端重新计算另一套绩效 |
| Streamlit 启动器及 CLI | `run.py`、`run_pipeline.py`、`stockrl/cli.py` | 迁移期间可并存；最终 Web 默认入口切换，CLI 继续离线可用 |
| 历史市场文件及旧数据库保留 | `stock_data/`、根目录 `experiments.db`、历史 CSV | 必须保留，不能据文件名推定可迁入新数据库 |

上述是源码和已有文档检查的结论。本轮未重新训练、运行全套测试或启动新服务；[旧验证记录](../verification.md) 仅提供基线背景。

## 3. 必须保留的设计

1. 项目独立研究 RL 自主进入、持有、减仓和退出，不依赖 StockTrader 的截面预测或选股信号。
2. 日线、单资产、只做多、无融资无卖空；观察 t 收盘，下一交易行开盘执行，再按其收盘估值。
3. 动作到目标仓位的映射、费用一次计入净值、现金与持仓限制、尾部截断及共同基准环境。
4. 按时间划分收益区间；只在训练段拟合归一化，用验证段选检查点；不使用测试结果挑选 seed。
5. CSV 离线实验、明确标注的合成演示、PPO/SAC、多个 seed、保存与原样重放。

这些是迁移时的行为基线，不表示现有交易假设已经足够接近全部真实市场规则。

## 4. 关键问题与迁移优先级

这里的 P1/P2 指重构交付优先级，并不声称现有个人研究工具存在对应等级的线上事故。

| 编号 | 优先级 | 架构问题与影响 | 提案中的处理 |
|---|---|---|---|
| R-01 | P1 | UI 直接进行长计算；增加接口外壳仍无法管理断线、取消和多次提交 | FR-03～05；ADR-0002：独立进程、持久队列和状态机 |
| R-02 | P1 | 输出文件存在不等于实验完成；崩溃留下的目录容易被误当作结果 | FR-04、06、08；ADR-0003：任务状态与产物完整性分别记录 |
| R-03 | P1 | 当前结果层使用内部路径；跨 HTTP 暴露路径会把实现细节和本地文件访问混在一起 | FR-01、06、08；数据集、任务、产物均通过 ID 访问 |
| R-04 | P1 | 前后端分别定义训练默认值、切分和指标，可能产生表面相同却语义不同的实验 | FR-02、07；单一领域规则、服务端规范化配置与 OpenAPI 契约 |
| R-05 | P1 | 新旧产物及重放目录存在不同含义，直接全量扫描可能重复登记或破坏来源关系 | FR-08；显式导入、版本适配和独立 replay ID |
| R-06 | P1 | 同时重写 RL、任务系统和 UI 会失去行为对照，无法判断指标变化原因 | C-02～05；ADR-0005；先保留语义，再分阶段切换 |
| R-07 | P2 | 简单回调缺少整组进度、生命周期和失联信息，换页后无法可靠跟踪 | FR-05；持久事件、阶段进度、轮询与心跳 |
| R-08 | P2 | 框架升级容易被理解为策略升级，但研究假设与风险比较并未因此成立 | FR-02、07；记录研究说明，禁止从短烟雾实验推出策略有效 |
| R-09 | P2 | 多个服务增加安装、启动、端口和依赖管理负担 | FR-09；本地启动器、同源静态交付、分离依赖及故障说明 |
| R-10 | P2 | 长期同时维护 Streamlit/React 两套完整产品会重复开发 | FR-10；过渡期并行验证，验收后移除活跃 Streamlit 入口 |

## 5. 三种实施路线

| 路线 | 收益 | 代价与局限 | 结论 |
|---|---|---|---|
| A：仅将页面替换为 React，接口同步调用训练 | 页面可以自由开发，初始改动较少 | 长任务和持久状态问题仍在，接口超时与重复执行风险需要随后重做 | 不推荐作为最终架构 |
| B：React + FastAPI + 单机 worker + 既有 RL 核心 | 完整隔离交互与计算；迁移可对照；本地部署可控 | 增加契约、数据库、进程生命周期和两套语言工具链 | 推荐 |
| C：前后端、RL 引擎同时重写，并直接引入分布式队列和多租户平台 | 有较大的组织和扩展空间 | 当前需求不支持该复杂度，策略语义回归和维护成本显著增加 | 暂不采用；需求变化后另立 ADR |

推荐 B 是针对当前本地研究需求的判断。React 官方说明，从构建工具起步仍需自己安排路由和数据获取；本提案因此明确这些责任，而不把 Vite 脚手架视为完整应用。[React 官方说明](https://react.dev/learn/build-a-react-app-from-scratch)

## 6. 策略路线如何与此次重构衔接

近期仍以自主仓位调整为研究主线：在预先确定的资产和交易约束下，比较 RL 与透明基准的扣费后表现。此处是研究方向说明，不宣称 RL 必须优于基准。

本轮规格要求记录研究目的、数据口径、成本、日期范围和比较对象，展示平均仓位、换手、风险与收益，避免只展示一条净值曲线。它不新增波动率目标策略、滚动样本外评估、跨资产泛化或统计显著性工具。缺少这些研究验证的限制必须可见，后续若要实现，应另起研究规格和验收。

这能防止两种混淆：换成 React 不会提供更好的交易信号；增加 FastAPI 也不会提高 PPO/SAC 本身的样本效率。

## 7. 提案假设与重审触发条件

| 当前提案假设 | 如果不成立，应重审什么 |
|---|---|
| 本机单用户，Windows 为首要环境，同时维护 Linux 兼容 | 公网或多人使用前，补身份、权限、隔离和部署规格 |
| 默认一个训练/重放任务执行，其他排队 | 多 GPU、多机器并发前，重审资源调度、队列和数据库 |
| 浏览器最多几秒更新一次进度即可 | 有高频实时数据要求时，评估 SSE/WebSocket |
| 本地文件系统足以保存数据与模型 | 对象存储、网络共享盘或团队共享前，重新设计一致性与锁 |
| 本轮保留算法、特征、奖励和市场模拟语义 | 改变这些语义时，为研究变更单独建立实验对照 |

## 8. 审查结论与下一步门槛

提案可以进入用户审阅；实现尚未开始。本轮自审检查了范围、任务状态、取消竞态、产物发布、旧数据兼容、前后端契约与验收追踪。具体要求以 Spec 为准。

自审已补全以下易产生歧义的内容：发布意图先于最终文件移动提交；新 replay 同时带上 load_bundle 所需的 training.json；应用实验 ID 与核心 run_id 分开；图表区分目标、成交后及收盘仓位；P10 的入口替换仅作为待 P11 验收的分支候选。它们是文档层面的澄清，不是已经实现的修复。

实施前需要确认本地单用户/单执行任务、分层迁移、历史产物只读导入和本轮不改变策略语义这些提案取舍。未来实现审查至少覆盖：真实 PPO/SAC 路径、刷新及 API 重启、任务取消和 worker 中断、历史重放、边界文件访问、干净安装与回退。只有运行证据成立，才能宣布新入口替代旧入口。
