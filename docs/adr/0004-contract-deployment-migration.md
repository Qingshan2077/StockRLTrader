# ADR-0004：契约协作、同源交付与渐进迁移

- 日期：2026-09-08；状态：Accepted for implementation，依据后续开发指令；契约生成及最终入口清理调整见 [ADR-0006](0006-static-only-implementation.md)。
- 关联：[Spec FR-09/10 与 HTTP 契约](../superpowers/specs/2026-09-08-react-fastapi-design.md)、[Plan](../superpowers/plans/2026-09-08-react-fastapi.md)。

## 背景

React 与 Python 分开后，配置、字段、错误和状态可能分别演化。现有用户主要在本机运行，要求整个工作流迁移，也要求历史数据不受损。需要兼顾前后端开发便利和最终使用步骤。

## 提议决定

使用版本化 `/api/v1` HTTP JSON 契约，Pydantic/OpenAPI 是线上输入输出类型来源；提交生成的前端 TypeScript 类型并在 CI 比较。领域约束由 Python 共享，前端验证只用于即时反馈，服务器必须重验。错误字段、分页、幂等和任务状态统一定义，不能每个页面自行设计。

开发时 Vite 代理 API；正常本地交付由 FastAPI 托管构建后的 SPA，同源调用接口，独立 worker 负责计算。路由回退只服务页面地址，不吞掉 `/api` 的 404。无需为此次本地交付引入 Nginx、容器编排或 Node SSR 常驻服务。

本地 API 只绑定 loopback，明确配置 Host、Origin 和内容类型检查。CORS 控制浏览器跨来源访问，并不是身份认证或完整本地访问隔离。[FastAPI CORS 文档](https://fastapi.tiangolo.com/tutorial/cors/)

默认采用轮询任务/事件，不要求 WebSocket 或 SSE。未来改推送时仍以数据库快照和事件序号恢复状态，不能让断线破坏任务身份。

迁移分为保留基线、建立服务与 worker、React 完成全流程、旧数据兼容验证、切换入口、移除 Streamlit 活跃依赖。旧页面放在原目录作为过渡对照，React 放入新目录，不做一次性覆盖。

`run.py` 最后才切换为本地启动器；原有 CLI 始终可独立使用。切换前保存代码回退点和一致性数据备份；回退不删除新数据或自动降级 schema。具体启动、停止、导入与恢复说明作为交付的一部分。

## 备选方案

| 方案 | 好处 | 未采用原因 |
|---|---|---|
| 手写两份 API 类型 | 开始快 | 随改动漂移，无法保证配置和状态一致 |
| 永久两套完整 Web | 用户有不同入口 | 重复开发、重复测试和功能不一致会长期存在 |
| 一次性删掉旧入口再重做 | 表面过程短 | 缺少对照和可用回退点 |
| 浏览器持续 WebSocket | 更新及时 | 当前训练秒级进度无需增加连接管理和重连协议 |
| 默认云服务/容器集群 | 可部署范围广 | 当前没有相应使用需求，扩大运维范围 |

## 影响与代价

前后端能围绕稳定契约分别实现，最终用户无需手工维持 Node 开发服务器。构建、静态深链接和 Python 打包成为新的维护责任；类型生成只能验证结构，金额、日期和研究语义仍依赖行为测试。

最终移除 Streamlit 必须以完整功能验收为前提，不能只因 React 首页能够打开就完成迁移。源代码安装和包含前端构建的交付方式都必须明确，缺少构建时启动器应给出可执行的修复说明。

## 验证与重审条件

AC-02、AC-06～09、AC-13～15 覆盖契约、页面恢复和切换。多人/公网使用、桌面打包或高频推送需求出现时另立部署与身份设计，不能仅把监听地址改成 0.0.0.0 就宣称支持。
