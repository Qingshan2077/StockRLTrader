# ADR-0003：SQLite 元数据与不可变文件产物

- 日期：2026-09-08；状态：Proposed。
- 关联：[Spec FR-01/02/06/08](../superpowers/specs/2026-09-08-react-fastapi-design.md)、[ADR-0002](0002-local-job-lifecycle.md)。

## 背景

已有实验以目录保存模型、归一化、行情与报表，便于 CLI 重放。目录扫描不适合表达提交但未执行、取消或中断的任务。根目录 `experiments.db` 是此前保留的历史文件，不能把它当成新应用的空数据库。

## 提议决定

新建 `outputs/app/state.sqlite3` 管理数据集索引、实验、任务、事件、幂等记录、产物索引与 schema 版本。模型、CSV 和日志保留为文件；新数据集保存不可变快照，新实验引用精确数据版本及过滤后数据指纹。数据库不存模型二进制或完整时序表。

SQLite 使用 WAL、短事务、外键和忙等待，数据库与锁都位于同一台机器的本地磁盘。WAL 允许读取与写入并行，但仍然一次只能有一个写者，且不适合网络文件系统；这正是本方案保持单机和短写事务的原因。[SQLite WAL 文档](https://www.sqlite.org/wal.html)

新产物保留已有核心布局，另加版本化 manifest、不可变请求与来源关系。文件索引使用受控根目录和相对路径，API 使用产物 ID。核心内部旧绝对路径字段通过适配器转换，不能泄漏为浏览器文件操作接口。

数据集、应用实验 ID、任务 ID、核心 run_id 分开。一个训练实验包含多个 seed；重放有自己的应用实验 ID，并指向来源实验，不能复用旧 run_id 做主键。

任务先写 staging；全部必要产物核验后才发布到最终目录。文件移动和数据库提交无法组成跨系统原子事务，因此记录发布凭据并测试崩溃窗口。成功必须同时满足合法任务状态、可信凭据和完整 manifest，不能用“summary.json 存在”推定。

历史无 manifest 的目录按 legacy-v0 只读导入。完整训练、旧 replay、残缺、损坏和未来未知版本分别处理；重复扫描不得重复登记。历史文件不被升级器原地改写，根目录旧数据库不被打开迁表。

## 备选方案

| 方案 | 好处 | 未采用原因 |
|---|---|---|
| 继续只扫描 JSON/CSV | 简单、便携 | 难以可靠实现状态、领取与幂等 |
| 全部数据和模型放 SQLite | 单文件看似方便 | 模型和长时序导致数据库膨胀，也破坏现有目录重放方式 |
| PostgreSQL + 对象存储 | 适合团队和多机部署 | 当前本地单用户无需两个额外服务 |
| 直接复用旧 experiments.db | 少一个文件 | 历史结构和语义不同，容易损坏用户保留数据 |

## 影响与代价

查询与研究产物各用合适载体，保留离线可搬移实验；代价是同时维护数据库版本、产物版本和两者一致性。来源未知或依赖不兼容的旧报告可以浏览，但不自动保证能够执行模型。

新 replay 复制重放所需源快照、模型和归一化，增加磁盘占用，换取移动目录后的自足性；来源关联仍保留。首版不提供自动清理或垃圾回收，以免在依赖关系未确认时删除证据。

备份使用 SQLite 一致性备份机制，或确认所有进程停止并完成 checkpoint 后再复制；不能在 WAL 写入期间只拷贝主数据库文件。数据库和相关快照/产物一起记录备份范围。

## 验证与重审条件

AC-01～03、AC-08、AC-10～12 验证快照、索引、重放和崩溃恢复。出现多机共享、较高写并发、对象存储或磁盘规模问题时重审存储方案；对外实验 ID 与版本契约不应依赖 SQLite 特有实现。
