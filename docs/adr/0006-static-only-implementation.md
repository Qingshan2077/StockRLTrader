# ADR-0006：本地实施与静态验证边界

- 日期：2026-09-08；状态：Accepted，依据用户后续明确开发指令。
- 补充 ADR-0004，保持其动态验收与最终清理目标。

## 决定

本轮在一个新工作树 `.worktrees/react-fastapi`、一个新分支 `refactor/react-fastapi` 实施全部应用层迁移。所有代码保留本地，不推送、不合并 main。文档分支此前的推送授权不延伸到本次代码。

用户明确要求“不运行构建，只编写代码并静态检查”。因此只执行源码 AST/TOML/JSON 检查、Ruff、TypeScript `--noEmit`、契约注解一致性和静态审查。可以编写回归测试，但不能运行测试、构建、训练、应用导入、服务、浏览器验收或故障注入。安装静态检查工具时禁用包生命周期脚本。

Pydantic 模型仍为契约来源。当前 TypeScript 文件由模型源码 AST 生成，能在不导入应用的情况下检查注解同步；保留 OpenAPI 导出与类型生成命令供后续实际契约验收，不宣称两者已在运行时完全一致。

本分支的 `run.py` 是新入口候选，主分支保持不变。由于 FR-10 所需动态证据无法在此次获得，保留可选旧 Streamlit 入口及对应依赖分组；不提前删除回退对照。React 构建文件和验证后的交付包也未生成，源码启动步骤明确要求后续构建。

## 代价与后续

静态检查可以发现语法、名称、类型、状态更新与路径边界等错误，但不能证明 Windows 进程行为、前后端集成、真实模型训练、取消/发布竞态或产物重放正确。AC-01～15 的动态部分继续等待后续执行授权和实际记录。

本轮完成的定义是代码与静态审查交付。最终运行验收、旧界面清理、主分支切换和推送是后续独立动作，不因代码已写完自动发生。
